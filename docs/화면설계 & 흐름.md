PART 1. CREATOR 상세 설계
1-1. SDK 코드 구조
CREATOR가 페이지를 만들 때 작성하는 코드는 아래 구조를 따른다.
파일 구조
my-page/

├── index.tsx          ← 메인 React 컴포넌트

├── schema.json        ← 커스터마이즈 스키마 정의

└── meta.json          ← 페이지 메타 정보
index.tsx — 메인 컴포넌트
import { PageProps } from '@joycraft/sdk';

export default function YesNoChaseButton({ data }: PageProps) {

const {

    questionText,

    yesButtonColor,

    noButtonSpeed,

    fontFamily,

    backgroundImage,

} = data;

return (

    <div style={{ fontFamily }}>

      <h1>{questionText}</h1>

      <button style={{ background: yesButtonColor }}>예</button>

      <button className="chase-button">아니오</button>

      {/* 아니오 버튼은 커서가 다가가면 도망가는 로직 */}

    </div>

);

}

핵심: data 객체 안에 CUSTOMER가 편집한 값이 들어온다. CREATOR는 이 props를 받아서 렌더링만 하면 된다.
schema.json — 스키마 정의
{

"fields": [

    {

      "key": "questionText",

      "type": "text",

      "label": "질문 문구",

      "placeholder": "나 좋아해?",

      "default": "나 좋아해?",

      "required": true

    },

    {

      "key": "yesButtonColor",

      "type": "color",

      "label": "예 버튼 색상",

      "default": "#ff6b6b"

    },

    {

      "key": "noButtonSpeed",

      "type": "number",

      "label": "아니오 도망 속도",

      "min": 0.5,

      "max": 3.0,

      "step": 0.1,

      "default": 1.5

    },

    {

      "key": "fontFamily",

      "type": "font",

      "label": "글꼴",

      "default": "Pretendard"

    },

    {

      "key": "backgroundImage",

      "type": "image",

      "label": "배경 이미지",

      "default": null,

      "required": false

    }

]

}
스키마 필드 타입 (CUSTOMER 에디터에서 자동 생성되는 UI)
type
에디터에 표시되는 UI
설명
text
텍스트 입력창
한 줄 텍스트
textarea
여러 줄 텍스트 입력창
편지 내용 등 긴 글
image
이미지 업로드 버튼 + 미리보기
클릭 → 파일 선택 또는 드래그
color
컬러 피커
원형/팔레트 선택기
font
폰트 드롭다운
플랫폼 제공 폰트 목록에서 선택
number
슬라이더 + 숫자 입력
min/max/step 지정 가능
select
드롭다운
options 배열로 선택지 제공
boolean
토글 스위치
on/off 설정


이 스키마가 플랫폼의 핵심 — CREATOR가 스키마를 정의하면, 플랫폼이 자동으로 CUSTOMER용 편집 패널을 생성한다.
meta.json — 메타 정보
{

"name": "예/아니오 도망 버튼",

"description": "아니오를 누르려 하면 버튼이 도망가는 인터랙션",

"category": "인터랙션",

"tags": ["질문", "고백", "재미"],

"useCases": ["연인", "고백", "생일"],

"platformMode": "responsive",

"thumbnail": "./thumbnail.png"

}

핵심 동작 설명:

드래그로 순서 변경

하단 "페이지 추가" → 페이지 둘러보기 모달 열림

중앙 미리보기:

선택한 페이지의 실시간 렌더링
우측에서 값을 바꾸면 실시간 반영

우측 편집 패널:

선택한 페이지의 schema.json에 정의된 필드가 자동 생성
필드 타입별 UI:
text → 텍스트 입력창
textarea → 여러 줄 입력창
image → 업로드 버튼 + 썸네일 미리보기
color → 컬러 피커 (팔레트 + 직접 입력)
font → 드롭다운 (플랫폼 제공 폰트 목록)
number → 슬라이더 + 숫자 직접 입력
select → 드롭다운
boolean → 토글 스위치

PART 3. 스키마 → 에디터 자동 생성 핵심 흐름
JoyCraft 플랫폼의 핵심 메커니즘을 정리.

CREATOR가 schema.json 정의

        ↓

플랫폼 DB에 schema 저장 (component_types.schema jsonb)

        ↓

CUSTOMER가 해당 페이지를 템플릿에 추가

        ↓

에디터 우측 패널이 schema를 읽어서 UI 자동 생성

        ↓

CUSTOMER가 값을 입력/변경

        ↓

변경된 값이 overrides (jsonb)로 저장

        ↓

렌더러가 default_values + overrides를 merge

        ↓

merge된 data를 React 컴포넌트에 props로 전달

        ↓

페이지 렌더링
데이터 흐름 예시
schema.json (CREATOR 정의):

questionText: { type: "text", default: "나 좋아해?" }

default_values (CREATOR 프리셋):

{ "questionText": "나 좋아해?" }

overrides (CUSTOMER 편집):

{ "questionText": "승현아 나 좋아해?" }

최종 렌더링 data (merge 결과):

{ "questionText": "승현아 나 좋아해?" }

→ <h1>승현아 나 좋아해?</h1>

CUSTOMER가 특정 필드를 안 바꾸면 overrides에 해당 키가 없고, default_values가 그대로 사용된다.
