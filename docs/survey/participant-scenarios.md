# 설문 참여자 시나리오

관리자 화면을 제외하고, 참여자가 연구 동의 화면부터 종료 화면까지 이동하는 경우를 정리한다.

## 공통 흐름

연구 동의 → 번호 입력(선택, 커피 기프트콘 이벤트) → 출생 연도·국적·거주지 확인 → 그룹 배정 → 홍보물 보기 → 설문 문항 → 주의 점검 및 남은 문항 → 완료 저장.

- 출생 연도 보기는 **2026년부터 1900년까지 127개를 모두 표시**한다. 불성실 응답자를 걸러내기 위한 패턴이므로 범위를 숨기지 않는다. 보기 범위 변경과 별개로 기존 참여 조건인 1995~2006년생 판정은 유지한다.
- 연구 동의 직후 번호 입력(이벤트) 화면이 나온다. 번호를 입력하려면 개인정보 수집에 별도로 동의한다. 번호 없이 참여할 때는 연구 참여 동의만 필요하다.
- `COMPLETE`만 응답·선택 전화번호를 최종 보관한다. `IN_PROGRESS`는 검증·쿼터 예약을 위한 임시 데이터다.
- `SCREENOUT`, `QUOTAFULL`은 화면에 전달하는 결과 코드이며 해당 상태의 결과를 새로 보관하지 않는다. 주의 점검 실패는 별도 종료 상태 없이 `COMPLETE`로 보관하고 `attention_failed` 표시만 남긴다.
- 이탈은 창 종료 여부가 아니라 서버의 마지막 활동·쿼터 예약 만료를 기준으로 정리한다. 기본 유휴 만료는 30분, 정리 주기는 1분이다. 따라서 정확히 30분이 되는 순간 화면이 자동으로 바뀌지는 않는다.

## 사람별 기본 사례

| 참여자 | 가정한 행동 | 참여자가 보는 결과 | 최종 보관 |
|---|---|---|---|
| A | 동의 → 번호 입력 → 모든 조건·문항 통과 | 응답이 제출되었습니다 | 응답 + 번호 |
| B | 동의 → 번호 없이 참여 → 모든 조건·문항 통과 | 응답이 제출되었습니다 | 응답만 |
| C | 동의 → 번호 입력 → 국적 등 참여 조건 불충족 | 참여 대상이 아닙니다 | 없음. 임시 응답 삭제 |
| D | 동의 → 번호 입력 → 끝까지 응답했지만 주의 점검 오답 | 응답이 제출되었습니다 | 응답 + 번호. 성공 처리하며 주의 실패 표시만 남김 |
| E | 동의 → 번호 입력 → 중간에 30분 넘게 활동하지 않음 → 정리 후 제출 | 참여 시간이 만료되었습니다. 처음부터 다시 참여해 주세요 | 없음 |
| F | 동의 → 번호 입력 → 중간에 새로고침 | 연구 동의 화면(처음부터), 동의·번호 해제, 진행 초기화 | 기존 미완료 참여는 다음 시작 또는 만료 정리 시 삭제 |
| G | 마지막 제출에서 저장 실패 | 현재 문항 유지 + 연결 확인 안내 | 완료 보관 없음. 재시도 성공 시 응답 + 번호 |
| H | 서버 저장 성공 후 응답만 네트워크에서 유실 | 일단 오류 안내 → 재시도하면 완료 화면 | 최초 저장 1건만. 번호·쿼터 중복 저장 없음 |
| I | 페이지 진입 기록 요청이 유실됨 | 진입 기록 재전송 후 자동 재시도 | 정상 완료하면 보관 |
| J | 요청이 너무 빨라 제한됨 | 1초 기다린 뒤 한 번 자동 재시도 | 정상 완료하면 보관 |
| K | 같은 번호의 다른 사람이 먼저 완료 | "이미 해당 번호로 등록된 설문이 있습니다" 안내 → 다시 누르면 번호 없이 응답 제출 | 기존 경품 번호 유지. 뒤 참여자는 응답만 |
| L | 동의 후 번호 입력 화면에서 이미 완료 등록된 번호를 입력 | 이미 설문을 완료하셨습니다 | 기존 완료 건 유지, 새 참여 시작 안 함 |
| M | 그룹 정원이 모두 예약·완료로 찬 상태에서 배정 시도 | 목표 인원이 모두 모였습니다 | 없음 |
| N | 필수 문항을 비워 둔 채 다음 클릭 | 미응답 문항 안내, 같은 페이지 유지 | 아직 완료 보관 없음 |
| O | 출생 연도 목록 열기 | 2026~1900년 127개 전부 표시 | 선택·완료 여부에 따라 결정 |

**D는 정상 완료로 처리되어 응답과 경품 번호가 그대로 보관된다.** 주의 점검 실패 여부는 관리자 화면·내보내기의 `attention_failed`로만 구분하며, 응답자에게는 알리지 않는다.

## 이탈·복귀의 세부 분기

| 상황 | 현재 동작 |
|---|---|
| 같은 화면을 열어 둔 채 짧게 자리를 비움 | 만료 정리되지 않았다면 현재 문항을 이어서 제출 가능 |
| 다른 탭으로 이동하거나 화면이 숨겨짐 | 홍보물의 활성 노출 시간은 증가하지 않음. 돌아와 남은 시간을 봐야 함 |
| 홍보물이 보이는 상태로 자리를 비움 | 화면이 보이는 시간은 누적됨. 실제로 사람이 보고 있는지까지 감지하지는 않음 |
| 30분이 지났지만 정리 작업 전에 제출 | 요청이 먼저 처리되면 진행될 수 있음. 만료 경계는 스케줄러·요청 실행 순서에 영향받음 |
| 정리 대상 선정 직후 활동이 갱신됨 | 잠금을 잡은 뒤 만료를 재검사하여 살아 있는 참여는 삭제하지 않음 |
| 정리 작업과 완료 제출이 겹침 | 완료됐거나 다른 요청이 잠근 참여는 정리에서 제외 |
| 중간에 창을 닫고 같은 브라우저에서 다시 시작 | 이전 쿠키의 미완료 참여를 삭제하고 첫 페이지부터 시작 |
| 창을 닫고 돌아오지 않음 | 유휴 만료 후 임시 응답·방문 기록 삭제, 예약 인원 반환 |
| 중간에 사용자가 선택한 번호 없이 다시 참여 | 새로운 익명 참여로 시작. 이전 전화번호로 복원하지 않음 |

## 여러 사람이 겹치는 경우

1. **서로 다른 브라우저·기기, 서로 다른 번호:** 각 쿠키로 독립 진행한다. 같은 네트워크라는 이유로 자동 차단하지 않는다.
2. **서로 다른 브라우저·기기, 같은 번호:** 둘 다 시작할 때는 미완료이므로 진입할 수 있다. 먼저 완료한 번호만 등록되고, 뒤 완료 요청은 충돌한다. 뒤 참여자는 번호 없이 응답만 제출할 수 있다.
3. **번호 없이 여러 번 참여:** 전화번호 기준 중복 차단을 적용할 수 없다. 새 참여마다 별도 응답이 생성될 수 있다.
4. **같은 브라우저의 탭 두 개:** `sv_rid` 쿠키를 공유하므로 독립 참여가 아니다. 두 번째 탭의 새 시작이 첫 번째 미완료 참여를 폐기하고 쿠키를 교체한다. 첫 탭이 계속 제출하면 페이지 불일치나 두 번째 참여로의 요청 연결이 생길 수 있다. 현재 다중 탭 격리가 없다.
5. **마지막 그룹 자리에 동시 신청:** DB 조건부 예약과 행 잠금으로 인원 초과를 방지하도록 구현되어 있다. 실제 동시 DB 실행 검증은 별도 통합 테스트 환경이 필요하다.
6. **관심 여부 선택 직전에 해당 보기가 마감:** 서버가 `QUOTA_FULL`을 보내면 같은 페이지를 다시 받아 마감 보기를 비활성화한다. 이 과정에서 그 페이지의 선택값은 초기화된다.

## 검증 방법과 범위

```powershell
npm.cmd run test:survey-scenarios
```

이 명령은 별도 Chrome/Edge 임시 프로필과 로컬 Vite 서버를 실행하고 끝나면 종료한다. `CHROME_PATH`, `SURVEY_TEST_PORT`, `SURVEY_DEBUG_PORT`로 실행 파일·포트를 변경할 수 있다.

- A~O: 실제 React 참여자 화면을 클릭하는 브라우저 시나리오다. 대표 문항으로 구성된 6페이지 목 설문을 처음부터 끝까지 사용한다. 운영 연구의 모든 문항·그룹별 문구를 검증하는 테스트는 아니다.
- G~M의 네트워크·만료·쿼터·중복 상황은 해당 API 응답을 주입하여 화면 분기를 검증한다. 특히 E는 실제로 30분 기다리는 테스트가 아니다.
- 브라우저 시나리오에서는 홍보물 타이머를 0초로 설정한다. 별도의 `DwellAccumulator`·`SurveyCompletionTest`가 숨겨진 시간 제외와 45초 서버 검증을 다룬다.
- `SurveyIdleScenarioTest`는 서로 다른 임시 응답자들의 만료, 직전 활동, 직전 완료, 제출 중 잠금, 중복 정리를 서버 서비스 수준에서 검증한다. 저장소·트랜잭션은 모의 객체다.
- `SurveyCompletionTest`는 완료 조건, 선택 번호, 실패 제외, 롤백 요청, 재시도 멱등성을 검증한다.
- PostgreSQL 행 잠금·동시 요청·마이그레이션 자체의 실제 동작은 여기서 검증하지 않는다. `SurveyIntegrationTest`의 별도 DB 실행이 필요하다.

## 확인된 제약

- 같은 브라우저의 여러 탭을 참여자별로 분리하지 않는다.
- 주의 점검 실패자도 완료로 보관되므로 분석 시 `attention_failed`로 직접 제외해야 한다.
- 중복 번호 충돌 안내는 토스트이고, 뒤 재시도에서는 번호가 제외된다. 안내를 놓치면 경품 없이 제출되는 것을 모를 수 있다.
- 개인정보 동의 체크박스는 번호 확인 요청 중에도 변경할 수 있다. 확인 요청을 보낸 직후 동의를 해제하는 상황에 대한 별도 방어가 필요하다.
