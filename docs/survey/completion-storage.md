# 설문 완료 저장 정책

- 번호 입력은 선택이다. `번호 없이 설문 참여하기`로 경품 신청 없이 응답할 수 있다.
- 전화번호는 참여 중 React 메모리에만 유지한다. 새로고침하거나 창을 닫고 다시 열면 입력과 진행이 초기화된다.
- `/start`는 기존 전화번호나 쿠키로 이어하기를 하지 않는다. 이전 쿠키가 가리키는 미완료 참여가 있으면 쿼터 예약을 반환하고 임시 응답을 삭제한다. 완료 응답은 보존한다.
- 페이지별 검증, 자극물 체류 시간 검증, 동시 쿼터 배정을 위해 진행 중 응답은 DB에 임시 유지한다. 관리자 결과·통계·CSV에는 `COMPLETE`만 포함한다.
- `SCREENOUT`, `QUOTAFULL`은 종료 응답을 보낸 뒤 보관하지 않는다. 주의 점검 실패는 `COMPLETE`로 보관하고 `attention_failed`만 표시한다. 응답·방문 기록·쿼터 예약을 같은 트랜잭션에서 정리한다.
- 창 종료 이벤트에 의존하지 않는다. 돌아오지 않은 참여는 기존 만료 정리 작업이 삭제한다. 기본 유휴 만료는 30분이며 작업 주기는 1분이다. 기존 실패·이탈 기록도 이 작업의 정리 대상이다.
- 번호는 페이지 제출 본문의 선택 필드 `phone`으로 전달하지만, `COMPLETE`로 전환되는 트랜잭션에서만 경품 테이블에 저장한다. 응답·완료 상태·쿼터 확정·번호 저장 중 하나라도 실패하면 완료 처리가 롤백된다.
- 별도 `POST /gift/phone` 저장 API는 제거했다. web과 API를 함께 배포해야 한다.
- 완료 저장 응답을 받지 못해 마지막 페이지를 다시 제출해도 기존 완료 결과를 반환한다. 번호나 쿼터를 중복 저장하지 않는다.
- 이미 완료 등록된 번호는 다른 응답자에게 덮어쓰지 않는다. 동시에 같은 번호로 완료하려는 경우 뒤 요청은 롤백되고, 사용자는 안내를 확인한 뒤 번호 없이 응답을 제출할 수 있다.
- CSV의 `gift_phone` 열은 정상 완료 시 함께 저장한 선택 전화번호다.

## 진행 순서와 탈락 번호

- 순서: 연구 안내·동의(서버 CONSENT 페이지) → 번호 입력(이벤트 참여, 선택) → 나머지 문항. 번호는 동의 직후에 받고, 이후 모든 페이지 제출 본문에 실어 보낸다.
- 참여 조건 탈락(`SCREENOUT`) 시 번호를 입력했다면 `sv_blocked_phone`에 번호만 저장한다(응답은 보관하지 않음). 이후 같은 번호는 `/gift/phone/check`가 `NOT_ELIGIBLE`을 반환해 다시 참여할 수 없다. 번호 없이 참여한 탈락자는 식별할 수 없어 막지 못한다. 테스트 설문 초기화 시 함께 삭제한다.

## 검증

Web: `npm.cmd run build`, `npm.cmd run lint`, `npm.cmd run test`.

API: `gradlew.bat test`는 DB 없는 회귀 테스트를 포함한다. `SurveyCompletionTest`는 완료·번호 없는 참여·실패 제외·재시작·트랜잭션 롤백·재시도를 검증한다.

실제 DB의 롤백과 번호 중복 제약 검증은 `SurveyIntegrationTest`의 완료 저장 테스트가 담당한다. 이 테스트는 기존 정책대로 `db.test=true`가 있어야 실행되며, 접속 대상과 테스트 데이터 격리를 확인한 환경에서 실행한다.
