# JoyCraft 전체 디자인 리팩터링 계획

작성일: 2026-09-14 · 상태: 계획안 / 구현 전

## 1. 목표와 기준

랜딩, 로그인 후 홈, 대시보드, 사이드바, 에디터, 관리자, 인증 모달, 플레이어의 서비스 UI를 하나의 디자인 시스템으로 전환한다. 색상뿐 아니라 폰트, 크기, 정보 위계, 간격, 버튼, 보더, 라운드, 그림자, 아이콘, 반응형, 상태 표현을 함께 변경한다. 개발 지침과 예제도 새 기준으로 교체하여 이후 작업이 이전 디자인으로 돌아가지 않게 한다.

기준 자료: `C:/bizbee/joy_craft/JoyCraft-editor-design-guide/`

- `JoyCraft-편집-UI-디자인-가이드.md`: 실제 편집 UI 명세 및 원본/확장 구분.
- `joycraft-editor.css`: 네임스페이스가 적용된 재사용 스타일.
- `editor-tokens.json`: 추출된 색상과 레이아웃 수치.
- `editor-style-reference.html`: 브라우저에서 대조할 기준 화면.
- `editor-original.css`, `class-mapping.json`: 원본과 통합 스타일의 대응 검증.

목표 인상은 밝은 회백색 바탕, 차분한 보라색, 얇은 경계선, 작은 라운드, 절제된 강조다. 편집 UI에는 원본 규격을 적용하고, 원본에 없는 랜딩·탐색·통계·인증 화면은 같은 색과 형태를 사용해 확장한다. 아래에서 **원본**과 **확장안**을 구별한다.

이 문서 작성 단계에서는 애플리케이션 코드와 기존 지침을 변경하지 않는다. 실제 전환은 아래 단계별로 진행한다.

## 2. 현재 코드에서 확인한 사항

| 구분 | 확인 내용 | 계획에 미치는 영향 |
|---|---|---|
| 기술 구성 | React 19, TypeScript, Vite, Tailwind 4, Zustand, React Router | 기존 기술 구성 안에서 전환 가능 |
| 기본 UI | `components/ui`에 TSX 20개, `components/nb`에 TSX 27개 | 중복 기본 컴포넌트를 통합해야 함 |
| 랜딩 | `NeoButton`과 `Nb*` 혼용, 인라인 색상·크기 존재 | 공통 토큰 교체만으로 완료되지 않음 |
| 전역 CSS | `index.css`에 팔레트, 테마, 픽셀 폰트, neo 유틸리티, 전역 제목 폰트 | 적용 범위를 나누고 호출부를 함께 이관 |
| 테마 | default/pastel/dark/mono, `joycraft-theme` 영속 저장 | 기존 저장값과 신규 테마 규격을 함께 처리 |
| 고객 레이아웃 | 실제 사이드바 펼침 너비 220px | CLAUDE의 고객 240px 설명과 불일치 |
| 에디터 | 좌측 목록 200px + 미리보기 + 우측 폼 320px | 참고 자료의 단일 사이드바 구조를 그대로 복사할 수 없음 |
| 홈 | 별도 HomePage 없이 `DashboardPage`가 고객 홈 담당 | 홈과 대시보드는 우선 같은 화면으로 설계 |
| 관리자 | `/master`와 users/sites/templates/settings가 같은 페이지 렌더링 | 모든 경로를 점검하되 없는 관리 기능을 디자인 작업으로 신설하지 않음 |
| 문서 | CLAUDE와 DESIGN_SYSTEM은 구 팔레트·픽셀·강한 그림자 강제 | 시작 단계에서 지침 전환 필요 |
| 추가 지침 | `.claude/agents/joycraft-builder.md`도 구 디자인 강제 및 과거 D: 경로 사용 | CLAUDE만 바꾸면 지침 충돌이 남음 |
| 검증 | build, lint, vitest 스크립트와 기존 테스트 3개 파일 | 기존 기능 검증 + 시각 검증을 결합 |
| 슬라이드 | 구현 컴포넌트 15개, 등록 ref 17개(하위호환 별칭 포함) | 개수는 레지스트리 기준으로 관리 |

전체 파일 내용의 정밀 감사와 브라우저 비교는 구현 0단계에서 수행한다. 현재 분석은 파일 목록, 라우트, 주요 구현, 스타일 및 지침을 기준으로 한다.

각 페이지는 정상·로딩·빈 결과·오류·재시도·작업 중·비활성 상태까지 완료 대상으로 기록한다. 기존에 해당 기능이 없는 상태는 구분하여 표시하고 실제 데이터와 연결된 상태만 제공한다.

### 슬라이드 콘텐츠와 서비스 UI 경계

모든 컴포넌트는 조사 목록에 포함한다. `src/slides/**`의 편지·휴대폰·3D 선물 같은 콘텐츠 자체는 참고 자료에서도 편집 UI와 별도 영역이다. 기본 계획에서는 각 작품의 시각 표현과 저장된 사용자 색상·폰트를 보존하고, 이를 둘러싼 앱 UI와 폴백·오류 표시를 전환한다.

슬라이드 내부까지 동일한 보라색 폼 스타일로 바꾸는 것을 뜻한다면 별도 콘텐츠 재디자인 작업량이 필요하다. 이 범위 가정은 구현 착수 시 명시한다. 서비스 컴포넌트의 누락을 허용하는 예외로 사용하지 않는다.

## 4. 디자인 규격

### 4.1 색상과 토큰

| 의미 토큰 제안 | 값 | 출처/역할 |
|---|---|---|
| `--jc-bg-app` | `#F8F7FA` | 원본 앱 바탕 |
| `--jc-bg-sidebar` | `#FCFBFD` | 원본 사이드바 |
| `--jc-bg-chrome` | `#FAF9FC` | 원본 툴바·캡션 |
| `--jc-bg-surface` | `#FFFFFF` | 원본 입력·선택 표면을 카드로 확장 |
| `--jc-bg-subtle` | `#F6F3F8` | 원본 반복 항목 바탕 |
| `--jc-bg-selected` | `#EDEAF1` | 원본 세그먼트 바탕을 선택 행으로 확장 |
| `--jc-text` | `#302C3A` | 원본 기본 텍스트 |
| `--jc-text-heading` | `#4F4559` | 원본 섹션 제목 |
| `--jc-text-control` | `#504557` | 원본 입력값 |
| `--jc-text-label` | `#8B7F93` | 원본 고밀도 폼 라벨 |
| `--jc-text-muted` | `#8A8291` | 원본 설명 |
| `--jc-border` | `#E8E5ED` | 원본 셸 경계 |
| `--jc-border-control` | `#E4DFE9` | 원본 컨트롤 경계 |
| `--jc-brand` | `#41314F` | 원본 브랜드 마크 |
| `--jc-focus` | `#847099` | 원본 포커스 |

나머지 원본 색은 `editor-tokens.json`의 역할별 값을 유지한다. 보라색을 하나로 합쳐 라벨·본문·비활성·선택 상태를 모두 같은 색으로 처리하지 않는다.

확장안: 주요 CTA에 브랜드색과 흰색 조합 사용. success/warning/danger/info와 hover/pressed/disabled/loading의 전경·배경·보더 토큰을 추가한다. 실제 색상값은 대표 화면에서 명도 대비를 확인해 확정하고 문서에 기록한다. 원본 삭제 텍스트 버튼은 원본 색을 유지하며, 탈퇴 등 위험 확인 액션에는 별도 danger 변형을 사용한다.

### 4.2 폰트와 크기

원본 폰트 스택: `-apple-system, BlinkMacSystemFont, "Segoe UI", "Noto Sans KR", sans-serif`. 플랫폼 기본 UI를 이 스택으로 통일한다. 원본 브랜드 마크의 Georgia는 별도 브랜드 규격으로 유지한다. Noto Sans KR이 목록에 있다는 사실을 폰트 파일 로딩으로 간주하지 않는다.

| 용도 | 편집기 원본 | 일반 서비스 확장안 |
|---|---|---|
| 메인 제목 | 28px | 랜딩 48px/모바일 32px, 페이지 28px/24px |
| 섹션 제목 | 12px | 20px/18px |
| 카드 제목 | 반복 항목별 원본 규격 | 16px, 굵기 600 |
| 본문 | 원본 영역별 10–12px | 14px, line-height 1.6 |
| 라벨 | 10px | 12px |
| 입력값 | 11px | 14px, 모바일 텍스트 입력은 16px 제안 |
| 버튼 | 원본 종류별 10–15px | 기본 14px, 작은 버튼 12px |
| 보조 메타 | 8–10px | 12px |
| 통계 수치 | 원본에 없음 | 28px, 숫자 정렬용 tabular-nums |

`density="compact"`는 원본 편집 규격, `density="comfortable"`은 일반 페이지 및 모바일 가독성 확장으로 정의한다. 실제 적용 시 CSS 클래스/변형으로 구현하고 페이지별 임의 숫자 덮어쓰기를 줄인다. 모바일 확대·포커스 시 가독성을 확인한다. 낮은 대비의 작은 원본 텍스트는 접근성 검토 결과에 따라 별도 확장 토큰으로 보완하고 원본값과 차이를 기록한다.

### 4.3 보더·라운드·그림자·간격

- 원본: 기본 선 1px, 포커스 2px 실선/offset 3px. 포커스를 레이아웃을 밀어내는 border로 구현하지 않는다.
- 원본 radius: 입력 8px, 점선 추가 9px, 재생 10px, 세그먼트 그룹 11px, 반복 항목 13px.
- 확장 radius: 앱 카드 13px, 다이얼로그 16px, 배지 pill. 값마다 의미 토큰을 부여한다.
- 원본 입력·항목 박스에는 그림자를 추가하지 않는다. 세그먼트 선택 그림자는 `0 1px 4px #3928420D`.
- 다이얼로그·드롭다운 등의 부유 요소만 별도 확장 그림자를 정의한다. 기본 카드·버튼의 검정 오프셋 그림자는 제거한다.
- 원본 편집 간격: 입력 padding 10px, label 위 13px/gap 7px, 2열 gap 9px, 항목 padding 12px, 섹션 세로 22px.
- 일반 앱 확장 간격: 4/8/12/16/24/32/48/64px. 페이지 좌우 32px/태블릿 24px/모바일 16px, 카드 padding 20px, 카드 간격 16px.
- 원본에는 hover 애니메이션이 없다. 일반 UI의 색상 전환을 추가한다면 120–160ms 확장 규칙으로 제한하고 reduced-motion 대응을 기록한다.

### 4.4 버튼·폼·아이콘

버튼 변형: primary, secondary, ghost, danger, dashed, icon. 기본 높이 40px, 작은 버튼 32px, 큰 CTA 48px는 서비스 확장안이다. 편집 전용 텍스트·재생·세그먼트 버튼은 원본 padding과 글자 크기를 유지한다. 모바일 주요 터치 액션은 44px 이상 영역을 확보하는 확장안을 적용한다.

모든 버튼에 disabled/loading/focus-visible을 정의하고 중복 제출 방지, loading 전후 너비 유지, 링크와 버튼의 의미 구분을 보존한다. 선택형 버튼 그룹은 원본처럼 `aria-pressed`, 실제 탭 패널 전환은 tab 의미와 키보드 동작을 사용한다.

폼은 text/number/textarea/select/color/file/checkbox/font/image/array를 각각 검토한다. 편집기의 숫자 spinner·select·checkbox는 원본 네이티브 방식을 유지한다. number 빈 값과 min/max/step 검증, 파일 업로드 상태, 색상 값 직접 입력, 배열 추가·삭제 동작을 보존한다. 투명 파일 input의 포커스는 외부 label의 focus-within으로 보여준다.

아이콘은 이미 설치된 `lucide-react`를 활용해 플랫폼 UI를 일관된 선형 아이콘으로 전환하는 안을 사용한다. 기본 16px, 보조 14px, 주요 탐색 18px와 동일한 stroke 규격을 문서화한다. 아이콘 단독 버튼에 접근 가능한 이름을 제공한다. 콘텐츠 작품의 고유 아이콘은 해당 콘텐츠 규격을 따른다.

## 5. 컴포넌트 통합 계획

최종 기본 컴포넌트는 `components/ui/`의 의미 중심 이름으로 통일한다. `Neo*`와 `Nb*`가 각각 새 시스템을 구현하는 상태를 남기지 않는다.

| 현재 대상 | 최종 방향 |
|---|---|
| NeoButton, NbButton | Button: variant/size/density/loading 공통 API |
| NeoCard, NbCard | Card: 표면·패딩·경계 변형, 임의 shadow 수치 API 폐기 |
| PixelIcon | Icon 또는 Lucide 직접 사용 규칙, 기존 이름 대응표 |
| SearchInput, NbInput, NbPasswordInput, NbTextarea | Input, PasswordInput, Textarea, Field, SearchInput |
| ToggleSwitch, NbSwitch | Switch 하나로 통합 |
| TabBar, NbTabs | SegmentedControl과 Tabs를 동작 의미에 따라 분리 |
| StatusBadge, NbBadge | Badge 기본형 + StatusBadge 도메인 래퍼 |
| DashedButton | Button dashed 변형 또는 얇은 도메인 래퍼 |
| NbCheckbox, NbRadioGroup, NbSelect, NbSlider, NbTagInput | Checkbox, RadioGroup, Select, Slider, TagInput |
| NbDialog, NbDropdown, NbTooltip, NbToast, NbAlert | Dialog, Dropdown, Tooltip, Toast, Alert |
| NbAccordion, NbAvatar, NbBreadcrumb, NbNavbar | Accordion, Avatar, Breadcrumb, 공통 탐색 구성 |
| NbPagination, NbProgress, NbSeparator, NbSkeleton, NbTable | Pagination, Progress, Separator, Skeleton, Table |
| StatCard, SiteCard, TemplateCard, UserRow, SectionHeader | 도메인 컴포넌트 유지 + 신규 기본형으로 내부 교체 |
| LoginModal, RegisterModal, TemplatePreviewModal | Dialog·폼·버튼 기반 통일 |
| ColorPicker | 스와치·직접 입력·선택 표시를 신규 규격으로 변경 |
| LiveThumbnail, ThumbnailSlideCanvas | 로딩·오류·프레임 전환, 썸네일 렌더 동작 보존 |
| RunAwayButton | 호출 위치 조사 후 서비스 UI 또는 콘텐츠 용도로 분류, 상호작용 보존 |
| SlideErrorBoundary, SlideCanvas | 오류·미지원 UI를 신규 기본형으로 변경 |

진행 방법:

1. 기본형을 구현하고 기존 호출부를 조사해 props 대응표를 만든다.
2. 필요할 때 기존 Neo/Nb export를 신규 기본형의 임시 어댑터로 제공한다. 임의 bg/color를 그대로 퍼뜨리는 호환 API를 영구 유지하지 않는다.
3. 도메인 컴포넌트 → 레이아웃 → 페이지 → 폴백 순으로 import와 props를 이관한다.
4. 사용처가 없는 Nb 컴포넌트는 검색으로 확인한 후 삭제하거나 신규 기본형으로 정리한다. 사용되지 않는 구 디자인 코드를 방치하지 않는다.
5. 호출부 이관 완료 후 어댑터, 구 export, 구 utility를 제거한다.

## 6. 화면별 설계 방향

### 랜딩

상단은 브랜드와 핵심 탐색·로그인·시작하기를 정돈한다. 히어로는 메시지와 실제 제작 예시를 중심으로 재배치하고, 화면 전체를 차지하는 원색·두꺼운 경계·장식 티커는 새 톤에 맞춰 정리한다. 제작 과정 → 예시/템플릿 → FAQ → 마지막 CTA 순으로 현재 콘텐츠를 재구성한다. 기존 클릭 흐름과 문구의 사실관계는 보존한다.

넓은 화면은 텍스트/예시 2열, 모바일은 1열. 콘텐츠 최대 너비 1200px, 섹션 간격 데스크톱 80px/모바일 48px를 확장안으로 사용한다. 로고 SVG, hero.png 등 기존 자산은 배경·외곽과의 조화를 확인해 재사용/조정 여부를 목록화한다.

### 고객 홈·대시보드

페이지 헤더에 환영 문구와 사이트 생성 액션을 배치한다. 통계는 흰 카드와 작은 상태 강조로 통일한다. 최근 사이트와 탐색 진입점을 아래에 배치한다. 데이터가 없으면 생성 동선을 안내하고, 통계 로딩을 0으로 오인시키지 않는다. 일반 콘텐츠 최대 너비는 1120px 확장안으로 통일한다.

### 내 사이트·탐색

헤더, 검색, 필터, 결과 개수, 카드 그리드의 순서를 통일한다. 카드의 미리보기 비율과 제목·메타·액션 위치를 맞춘다. 키보드/터치에서도 편집·공유 액션이 보이게 한다. 빈 목록과 검색 결과 없음은 다른 안내를 표시한다. 화면 폭에 맞춰 3/2/1열을 기본으로 하되 실제 카드 최소 너비를 기준으로 조정한다.

### 고객·관리자 사이드바

공통 AppShell/Sidebar/NavItem/PageHeader 규격을 만들고 고객·관리자의 메뉴 데이터와 권한만 다르게 연결한다. 상단 브랜드, 주요 메뉴, 계정 영역 순으로 정돈한다. 선택 메뉴는 연보라색 표면과 진한 텍스트, 구분은 1px 선으로 표현한다.

일반 탐색 사이드바 너비 240px는 확장안이다. 편집 폼용 원본 318px와 다른 용도로 구분한다. 모바일에서 현재 고객 하단 탐색이 있는 경우 새 스타일로 유지하고 관리자 탐색은 드로어로 제공한다. 중복 메뉴와 콘텐츠 가림을 확인한다.

### 에디터

현재 목록/미리보기/속성 패널 구조와 기능을 보존하며 참고 자료의 폼·툴바 디자인을 적용한다. 원본처럼 한 패널에 모든 기능을 억지로 합치지 않는다.

- 넓은 화면(1100px 초과): 좌측 페이지 목록 200px는 기존 기능에 맞춘 확장 규격, 중앙 미리보기, 우측 편집 폼 318px. 툴바 78px.
- 중간 화면(760px 초과~1100px): 편집 폼 285px, 페이지 목록은 접기/드로어로 전환하여 중앙 영역 확보.
- 모바일(760px 이하): 미리보기 중심, 페이지/편집 접근은 기존 탭 기능과 연결하되 열린 패널은 최대 min(340px,100%), 툴바 60px.
- 폼의 섹션 번호·제목·구분선·반복 항목·라벨·입력은 원본 규격 사용.
- PC/모바일 전환은 세그먼트, 다시 재생은 원본 재생 버튼, 저장·공개는 확장 액션 변형으로 구분.
- 하단 캡션을 채택할 경우 원본 47px/모바일 36px 사용. 실제 저장 상태와 안내 문구를 연결.
- `100dvh`, `min-width:0`, `min-height:0`, 패널별 내부 스크롤을 보장.
- `useFitScale`, ResizeObserver, 고정 스테이지 치수, 저장·공개 및 선택·재정렬 로직은 레이아웃 변경 후 재검증.
- 패널을 모달로 열면 Escape, 포커스 이동/복구, 배경 스크롤 잠금과 키보드 조작을 구현.

### 설정·인증·관리자·플레이어

설정은 섹션별 카드·일관된 필드·하단 저장 액션을 사용하고 저장 성공/실패를 같은 규격으로 표시한다. 테마 미리보기는 실제 토큰과 연결한다. 로컬 설정과 API 설정의 의미는 보존한다.

로그인·회원가입·카카오 콜백은 동일한 폼과 Dialog 규격을 사용한다. 소셜 로그인 표시의 고유 색은 브랜드 예외 토큰으로 관리한다. 관리자 목록은 행 간격·아바타·배지·구분선을 통일한다.

플레이어의 로딩·실패·종료·재시작과 미지원 슬라이드 안내를 새 디자인으로 바꾼다. 콘텐츠 캔버스에 전역 폼·버튼 reset을 적용하지 않는다.

## 7. CSS와 테마 구조

제안 구조:

```text
src/styles/
  tokens.css          공통 의미 토큰, 타이포, 간격, 라운드
  themes.css          신규 default와 기존 테마 ID별 완전한 토큰 집합
  base.css            서비스 UI 기본 규칙과 명시적 적용 범위
  editor.css          참고 자료 기반 편집 전용 규격
src/index.css         Tailwind와 위 스타일 진입점
docs/design/reference/ 원본 명세·CSS·JSON·HTML 사본
docs/DESIGN_SYSTEM.md  최종 서비스 디자인 명세
```

Tailwind 의미 클래스와 CSS 토큰의 연결은 한 곳에서 정의한다. 참고 자료의 원본 CSS는 대조용으로 보관하고, 실제 앱에는 네임스페이스를 가진 통합 CSS를 사용한다. `editor-original.css`를 전역 import하지 않는다.

`data-jc-editor-ui`는 편집 컨트롤 영역에만 적용한다. 앱의 스타일 범위 마커를 추가하더라도 슬라이드에 상속되는 font/color와 전역 h1/button/input 선택자를 반드시 따로 점검한다. 클래스 네임스페이스나 `isolation:isolate`만으로 CSS 상속이 차단된다고 간주하지 않는다. 포털 모달에도 테마와 토큰이 동일하게 적용되게 한다.

테마 기본안은 기능 보존이다. default를 참고 디자인으로 전환하고 pastel/dark/mono ID는 유지하면서 동일한 컴포넌트·라운드·보더 체계에 맞춘 토큰을 정의한다. 비기본 테마는 참고 자료에 없는 확장안으로 표시한다. 일부 구 토큰만 남아 버튼·입력·다이얼로그가 서로 다른 테마가 되지 않게 한다.

`joycraft-theme`의 기존 저장값, 유효하지 않은 값, 새로고침 복원, 설정 화면의 선택 상태를 검증한다. ID나 저장 구조를 변경하면 persist 버전과 migration을 함께 추가한다. 라이트 전용으로 축소하는 안은 별도 제품 결정이며 기본 계획에서 테마 기능을 삭제하지 않는다.

|---|---|---|---|
| 0. 현황 고정 | 전체 import·스타일·자산·상태 목록, 현재 화면 캡처, 기준 build/lint/test | 파일/라우트별 이관 체크리스트, 기준 화면·오류 기록 | 누락 없는 목록과 기존 실패 구분 |

단계마다 검토 가능한 작은 변경 단위로 나눈다. 공통 컴포넌트 교체와 페이지 이관은 빌드 가능한 상태를 유지한다. 첫 대표 화면에서 규격을 조정한 뒤 나머지 화면으로 확산한다. 사용자별 기존 작업과 `.claude/worktrees`는 건드리지 않는다.

작업량 추정은 1인 기준 총 15–25 작업일 정도의 초안이다: 조사/명세 2–3일, 기본형 3–5일, 셸/고객/랜딩 4–6일, 에디터/인증/관리자/플레이어 3–5일, 테마/정리/검증 3–6일. 실제 일정은 브라우저 기준선, 모달 동작 복잡도, 기존 오류에 따라 재산정한다. 슬라이드 콘텐츠 자체 재디자인은 이 추정에 포함하지 않는다.

## 10. 검증 계획

### 자동 검증

- 시작 시 `npm run build`, `npm run lint`, `npm run test`를 실행해 기존 실패를 기록한다.
- 변경 단계에 맞는 타입/린트/관련 테스트를 수행하고 통합 완료 시 세 명령을 모두 실행한다.
- 기존 editorStore, schemaAdapter, numberField 테스트로 저장·스키마·숫자 처리 회귀를 확인한다.
- 신규 테스트는 테마 저장값 이관, 버튼 중복 제출, 모달 포커스, 에디터 주요 저장 흐름처럼 의미 있는 동작 변경에 한정한다.
- 브라우저 자동화가 현재 구성에 없으므로 실행 환경을 확인한 후 도입 범위를 정한다. 시각 검증을 빌드 성공으로 대체하지 않는다.

### 브라우저·시각 검증

- 일반 화면: 1440/1280/1024/768/390/360px 폭.
- 편집기 경계: 1100px와 760px 전후에서 각각 1px 차이도 확인.
- 랜딩, 고객 홈, 목록, 탐색, 설정, 관리자, 편집기, 인증 모달, 플레이어 상태를 비교 캡처.
- 참고 HTML과 편집 폼·세그먼트·항목 카드·툴바를 같은 viewport에서 대조.
- 레이아웃·폰트 실측은 computed style로 확인. OS별 네이티브 폼/폰트 차이는 구분해 기록.
- 기본/비기본 테마, 긴 한글 제목, 긴 URL, 빈 목록, 많은 항목, 오류 메시지, 업로드 중 상태 확인.
- 모바일 패널의 스크롤, 키보드 표시 후 입력 가림, 툴바 잘림, 가로 스크롤, safe-area 확인.
- 키보드 탐색, 포커스 표시/복구, 입력 라벨 연결, 탭/세그먼트 의미, 읽기 순서, 텍스트 명도 대비 확인.
- 슬라이드 레지스트리 전체의 미리보기·실행 화면을 점검해 플랫폼 CSS 유입 여부 확인.

### 핵심 기능 회귀 시나리오

1. 랜딩 → 로그인/회원가입 → 콜백 → 고객 홈.
2. 사이트 생성 → 에디터 → 슬라이드 추가/선택/삭제/순서 변경.
3. 텍스트·숫자·색상·이미지·배열 편집 → 미리보기 → 저장 → 새로고침 복원.
4. 저장 실패/공개 실패 처리 → 재시도 → 공유 링크 → 플레이 → 종료/재시작.
5. 사이트 검색/필터 → 탐색 → 템플릿 미리보기 → 기존 선택 동작.
6. 프로필 저장·알림 변경·테마 전환 → 새로고침 → 선택값 복원.
7. 관리자 권한 접근 및 일반 사용자 접근 제한 유지.

공유 링크 복사 안내처럼 성공 표시를 정리하는 경우 실제 복사 성공/실패를 구분한다. 디자인 변경을 계기로 API 성공을 추정하는 UI를 새로 만들지 않는다.

## 11. 최종 완료 기준

- [ ] 모든 실제 라우트와 모달, 로딩/빈/오류 상태가 이관 목록에서 확인됨.
- [ ] 플랫폼 기본 UI에 구 픽셀 폰트·원색 패널·굵은 검정 보더·오프셋 그림자가 남지 않음.
- [ ] 모든 기본 컴포넌트가 하나의 토큰·변형 체계를 사용함.
- [ ] 에디터 원본 규격과 일반 페이지 확장 규격이 문서와 구현에서 일치함.
- [ ] 모바일 탐색·패널·긴 콘텐츠가 잘리지 않고 키보드로 조작 가능함.
- [ ] 기존 테마 저장값과 모든 지원 테마의 실제 표시가 검증됨.
- [ ] 저장·공개·업로드·인증·재생 등 기존 기능 회귀가 없음.
- [ ] 슬라이드 콘텐츠와 앱 스타일의 경계가 검증됨.
- [ ] Neo/Nb 임시 호환층과 미사용 구 스타일이 정리됨.
- [ ] CLAUDE, builder 지침, DESIGN_SYSTEM, 관련 설계 문서가 동기화됨.
- [ ] build/lint/test 및 실제 브라우저 검증 결과가 기록됨.

우선 실행 단위는 **기준선 조사 → 디자인 명세/지침 → 공통 기본형 → 편집기·고객 홈·랜딩 대표 화면 → 전체 화면 이관**으로 한다.
